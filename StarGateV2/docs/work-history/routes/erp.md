## 2026-08-30 · 성능 최적화 · 표시 캐릭터와 알림 조회 축소

- 대시보드가 쓰는 이름·코드네임·등급·초상·HP/SAN/포인트만 DB projection으로 읽고, 캐릭터 시트·로어 전문을 RSC/API에 직렬화하지 않는다. GM의 표시 NPC와 크레딧을 조회하는 경제 MAIN은 계속 별도로 선택하며 중복·소유권·ACTIVE GM fallback 정책은 유지한다.
- 최근 알림은 기존처럼 최대 5건을 표시하되 DB에서 20건을 읽고 자르는 대신 처음부터 5건만 조회한다.
- 실제 소유자 7명·캐릭터 8개의 main/display/byId 22회 비교가 모두 일치했다. 캐릭터 부분 JSON 평균은 9,009.68→230.32B(-97.44%), BSON 평균은 9,279.45→226.82B였다. 전체 대시보드 payload 절감률로 해석하지 않는다.
- 알림 결과도 7/7 동일했고 DB 조회 행은 110→34, BSON 합계는 30,167→9,069B로 줄었다. 브라우저로 보내는 알림 5건은 변경하지 않았다.
- 검증: GM 표시·MAIN·legacy·중복·비활성·소유권 mock 9건, 대시보드 계약 6건, `pnpm typecheck`, `pnpm lint`, `pnpm build`, 인증 GM 1280px·390px 신원·초상·가로 넘침 확인, critical risk review P0–P2 없음
- 관련 구현 커밋: `45d9fc0a`
- 운영 경계: 계정·캐릭터·크레딧·인벤토리·알림을 쓰지 않았으며 다른 작업의 아이콘·장비 변경은 커밋에 포함하지 않았다.
