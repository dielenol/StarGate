## 2026-08-17 · 기능 변경 · 1회 주문 50주 하드캡 제거

- 매수·매도 1회 주문 수량 상한 50주를 제거해 보유 전량 매도와 잔액 한도 매수를 한 번에 처리할 수 있게 했다. 기존에는 640주 보유 종목을 전량 정리하려면 50주씩 13회 주문해야 했다.
- 실질 상한은 매수=주문 가능 잔액, 매도=보유 수량이며 각각 transaction 내부(`addCredit` 음수 잔액 가드, `sellHolding` 의 `$gte` 필터)에서 원자적으로 재검증된다. 서버 검증에는 1주 이상 안전 정수 조건만 남겼다.
- 수량 규칙을 `lib/stocks/order.ts` 단일 출처로 모아 라우트 2곳과 거래 UI에 흩어져 있던 상수 중복을 없앴다. "최대" 비율 칩이 이제 보유 전량·잔액 전액 기준으로 동작하며, `1회 주문 한도` 힌트 행은 `주문 가능 잔액` / `보유 가능 N주` 안내로 대체했다.
- 수량 입력은 체결 가능 수량으로 clamp한다. 매수는 잔액으로 살 수 있는 수량, 매도는 보유 수량이 상한이며 입력창·증감 버튼·비율 칩이 같은 경로를 쓴다. 보유 132주에 13320000 같은 값이 찍히지 않는다.
- 검증: 웹 주식·거래 계약 61건, clamp 시나리오 9건, `pnpm typecheck`, 전체 `pnpm lint`, production build
- 관련 커밋: `88f70d13`, `d482e4ed`
- 운영 경계: 라이브 주문·주가·보유량은 변경하지 않았다.
