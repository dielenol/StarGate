## 2026-07-30 · 기능 개선 · 띠아 신제품 이미지·대사

- 신제품 공지에 등록된 상품 이미지를 크게 표시하고, 이미지가 없거나 안전하지 않은 경로면 공지를 실패시키지 않고 이미지 없이 발송하도록 했다.
- 띠아가 신제품을 직접 소개하고 권하는 말투로 출시 대사를 보강했다.
- 검증: 웹 계약 테스트 7개, worker 전체 테스트 39개, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `git diff --check`
- 관련 커밋: `54631c1`

## 2026-07-30 · 버그 수정 · 강제 종료 자동 해제

- GM 강제 종료를 영구 폐점 상태로 두지 않고, 설정 이후 첫 정상 개점 시각(한국시간 월~토 06:00)에 자동 운영으로 복귀하도록 변경했다.
- 서버 렌더 직후와 06:00·20:00 영업 경계마다 카탈로그를 다시 확인해, 화면을 계속 열어둔 경우에도 영업 상태가 자동 갱신되도록 했다.
- worker의 띠아 입고 웹훅도 웹과 같은 영업 판정을 사용해 만료된 강제 종료를 셔터 상태로 안내하지 않도록 통일했다.
- 검증: 영업 일정 집중 테스트 7개, core 전체 테스트 7개, worker 전체 테스트 44개, `pnpm typecheck`, 대상 ESLint, `git diff --check`, 인증 브라우저 1280×720 확인(가로 넘침·콘솔 오류 없음)
- 관련 커밋: `b90d1dc`

## 2026-07-31 · 성능 최적화 · 재고 refresh 웜패스 단락

- 카탈로그 조회가 매번 전 품목 refresh를 재수행하던 것을, 전 재고 1회 선조회 후 오늘 갱신분을 제외하고 stale 품목만 갱신하도록 바꿨다 (웜패스 DB 왕복 약 48회→1회, 일일 크론이 본 갱신 담당).
- 페이지와 catalog API의 중복 응답 조립을 `shop/_data.ts` 공유 빌더로 통합하고 영업 상태 조회를 refresh 체인과 병렬화했다.
- 검증: 웜패스 단락 테스트 7건 신규 + shop 스위트 44개(100-동시성 race 포함), `pnpm lint`, `pnpm typecheck`, `pnpm build`
- 관련 커밋: `58ccb35`

## 2026-07-31 · 기능 추가 · 미스터비스트 소다 복권 이벤트

- 활성 지급 기간에 미스터비스트 소다 구매 수량만큼 캐릭터 귀속 스크래치 복권을 함께 지급하고, 마우스·터치 긁기 또는 접근성 버튼으로 결과를 확인하도록 추가했다.
- 꽝부터 0등까지 7단계 확률표를 적용했으며, 0등은 `0.0001%` 확률로 `100,000 CR`을 지급하고 1등보다 강한 전용 광원·파티클 효과를 표시한다.
- 복권 권리를 이벤트·확률표 버전에 귀속된 1장 단위 원장으로 관리하고, 종료 후 사용·중복 요청·다중 탭·소유권 변경·거래 우회·필수 인덱스 누락을 안전하게 처리한다.
- 2등·1등·0등은 현재 공개 캐릭터만 최근 당첨 피드에 표시하며, 서버의 진행 중 복권을 기준으로 이어서 사용할 수 있다.
- 검증: 복권·거래 집중 테스트 15개, `pnpm typecheck`, `pnpm lint`, shared-db build, `pnpm build`, `git diff --check`, 인증 브라우저 데스크톱·390×844 확인(오류 오버레이·콘솔 경고·가로 넘침 없음)
- 관련 커밋: `e733a98`, 운영 스펙 `8962f0a`
- 후속 작업: 운영 활성화 전에 legacy 상태 점검, 필수 인덱스 적용, 비공개 master item dry-run 페이로드 반영 및 재조회가 필요하다.

## 2026-07-31 · 기능 개선 · 소다 일일 제한과 이벤트 포스터

- 미스터비스트 소다를 로그인 사용자 기준 한국시간 하루 최대 10개로 제한하고, 여러 주문·동시 요청에서도 10개를 넘지 않도록 결제 트랜잭션에 일일 카운터를 결합했다.
- 이벤트 활성 기간에는 소다와 복권 이미지를 사용한 전용 포스터를 노출하고, 소다 1개당 복권 1장·일일 제한·0등 100,000 CR 정보를 함께 안내한다.
- 이벤트 종료 경계와 결제 응답 유실이 겹쳐도 소다만 결제되거나 중복 결제되지 않도록 복권 기대조건과 장바구니 멱등 키 보존을 추가했다.
- 검증: 집중 테스트 22개 중 18개 통과·Mongo 통합 4개 환경 부재로 미실행, 대상 ESLint, `git diff --check`, 프로덕션 빌드, 인증 브라우저 1280×720·390×844 확인(가로 넘침·콘솔 오류 없음)
- 관련 커밋: `0b26f6e`
- 후속 작업: 이벤트 활성화 전에 격리 replica-set MongoDB에서 동시성·rollback·멱등 replay 통합 테스트 4개를 실행하고, 제한 적용 전 같은 KST 일자의 기존 소다 구매가 없도록 이벤트 시작 전에 배포한다.

## 2026-07-31 · 기능 개선 · 복권 이벤트 GM 운영 설정

- 환경변수 기반 이벤트 활성화를 제거하고, 편의점의 GM 전용 메뉴에서 이벤트 ID·시작/종료 시각(KST)·활성 상태를 직접 저장하도록 변경했다.
- DB 설정 문서가 없으면 안전하게 비활성화하며, 활성화 전 필수 인덱스와 비공개 복권 마스터 아이템 준비 상태를 화면과 API에서 확인한다.
- 동시 GM 저장은 설정 버전 CAS로 차단하고, 설정 변경·감사 outbox·결제 시점 활성 상태·캐릭터 소유권을 MongoDB transaction과 write fence로 보호한다.
- 검증: shop 전체 테스트 64개 및 집중 테스트 17개, 대상 ESLint, `pnpm typecheck`, `pnpm build`, `git diff --check`, 인증 브라우저 1280×720·390×844 확인(가로 넘침·콘솔 오류 없음)
- 관련 커밋: `6021161`
- 후속 작업: 운영 활성화 전에 별도 승인 범위에서 필수 인덱스와 canonical 비공개 master item을 준비하고, 격리 replica-set 환경에서 checkout↔비활성화·소유권 이전·감사 outbox 실패 경쟁 테스트를 실행한다.
