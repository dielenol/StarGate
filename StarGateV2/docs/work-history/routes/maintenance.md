# /maintenance — ERP 긴급 보안 점검

## 2026-10-23 · 기능 추가 · 예약 점검 공지와 자동 재개

- 기존 공개 사이트와 ERP 페이지를 보존하고, 비인가 접근 대응을 묘사하는 공식 비상점검 공지를 별도 화면으로 추가했다. 점검 일정·대상 범위·진행 업무·남은 시간과 접속 재확인 및 공개 아카이브 링크를 제공한다.
- 확정 일정은 한국시간 2026-10-25 20:00부터 2026-10-26 12:00까지다. 활성 구간에만 공지가 열리며 종료 뒤 서버 상태를 재확인한 후 기존 ERP로 이동한다. 조회 실패는 서비스 재개로 처리하지 않는다.
- `/maintenance/preview`는 개발 환경 전용이며 확정 일정의 시작 5분 뒤 상태를 표현한다. 실제 차단을 켜지 않고 검토할 수 있으며 운영 빌드에서는 404다.
- 검증: `pnpm typecheck`, `pnpm lint`, `pnpm build`, 일정·proxy 테스트 9건, 기존 게스트·로컬 접근 회귀 테스트 17건, 독립 lifecycle 실행 21건 통과. 느린 navigation 중 중복 이동을 방지하고 30초 마운트 유지·focus·visibility 재진입에서도 이동 1회를 확인했다.
- 화면 검수: 로컬 개발 브라우저의 실측 320×844·390×844·520×900·521×900·1440×1000에서 공지의 제목·일정·버튼·푸터를 직접 확인했고 가로 넘침이 없었다. 최종 공지 브라우저 콘솔 오류·경고 0건. 데스크톱·모바일 전체 캡처를 저장했다.
- 실제 동작: 짧은 시험 일정에서 게스트 인증으로 열어 둔 `/erp` → `/maintenance` → `/erp`의 자동 전환을 관찰했다. 로컬 production 서버에서도 공지 200, 미리보기 404와 ERP 차단을 확인했다. 시험 환경변수는 제거하고 확정 일정의 `scheduled` 상태로 복원했다.
- 운영 경계: 로컬 구현·검증만 수행했다. 운영 배포, 운영 일정 활성화, 업무 데이터 mutation은 수행하지 않았다.

## 2026-10-23 · UI 개선 · 긴급 보안 봉쇄 안내 강화

- 첫 시안에 대한 추가 요청을 반영해 제목을 ‘내부 업무망 긴급 봉쇄’로 강화하고, 비인가 접근 감지·업무 기능 중지·접속 경로 격리를 명확히 안내한다.
