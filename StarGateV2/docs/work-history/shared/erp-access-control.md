## 2026-10-23 · 기능 추가 · ERP 예약 점검 차단

- 한국시간 2026-10-25 20:00 이상, 2026-10-26 12:00 미만에 `/erp`와 `/api/erp` 루트·하위 경로를 인증·역할·로컬 page-lock 우회보다 먼저 차단한다. ERP GET/HEAD는 점검 공지로 이동하고 API 및 페이지 쓰기 요청은 `503 ERP_MAINTENANCE`, `no-store`, `Retry-After`를 반환한다.
- 모든 ERP provider 밖의 클라이언트 gate가 서버 시각 기준 예약 타이머와 상태 재확인으로 열린 탭을 닫는다. 종료 경계 이후에는 기존 인증·게스트·페이지 잠금 정책이 그대로 적용된다. 공개 사이트·인증·VTT·cron·worker는 이 차단의 대상이 아니다.
- 기본 예약은 `lib/maintenance/schedule.ts`에 있다. 시험용 `ERP_MAINTENANCE_START_AT`/`ERP_MAINTENANCE_END_AT`은 시간대가 포함된 두 ISO 시각을 함께 지정한다. `ERP_MAINTENANCE_DISABLED=1`은 비상 해제다. 부분·잘못된 설정은 `invalid`이며 차단하지 않으므로 실제 배포 전 대상 환경의 해당 값 유무와 `/api/maintenance` 상태를 확인해야 한다.
- 검증: 일정·실제 proxy 실행 테스트 9건, 기존 게스트·로컬 접근 회귀 17건, 독립 client lifecycle 21건, 타입 검사·린트·운영 빌드 통과. 읽기 전용 risk review 및 Astra 리뷰의 중복 navigation 지적 수정 후 재검토를 완료했다.
- HTTP 실행: 로컬의 시작 전 인증 이동, 활성 중 RSC·위조 세션 쿠키·로컬 우회 헤더 요청의 공지 이동, ERP API 7개 메서드와 Server Action의 503, 공개 홈·로그인 유지, 종료 후 원래 인증 경로와 API 라우팅 복원을 확인했다. 안전한 존재하지 않는 시험 경로로 쓰기 요청을 검증하여 업무 mutation은 실행하지 않았다. production 로컬 서버에서도 동일 차단과 개발 미리보기 404를 확인했다.
- 한계: 점검 시작 전에 이미 허용된 in-flight 요청을 취소하거나 외부 worker를 중단하는 기능은 아니다. 백그라운드 탭의 기존 실시간 연결은 gate가 실행되어 provider가 해제될 때 닫힌다. 배포 전에 열려 있던 구버전 클라이언트는 새 클라이언트 코드가 로드되어야 자동 화면 전환을 지원하며, 신규 서버 요청 차단은 별개로 적용된다.
- 운영 경계: 운영 반영 없이 작업 소유 로컬 커밋만 생성했다. 로컬 시험 일정을 제거하고 사용자 확정 예약으로 복원했다.
