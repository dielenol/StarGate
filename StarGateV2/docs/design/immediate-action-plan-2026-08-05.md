# 시즌 1 즉시 작업 구현·근거 원장

## 구현 범위

- 아르고 등록 준비, 네베드 전용무기 후보, ZULU-0028 연구소 v1, 미스터비스트 소다 불량 판정, 문학·철학 입력 통합, Nochichim 계약 보강을 다룬다.
- 시즌 2와 9화 아이디어, 이미 완료된 이동식 클레이모어 재구현, 라이브 DB·Discord·배포 mutation은 제외한다.
- 코드와 테스트, dry-run 페이로드까지만 구현한다. 운영 재료·크레딧·인벤토리·장비 상태는 별도 승인 전까지 바꾸지 않는다.

## 근거 정책

1. 현재 사용자 지시, 첨부 원문, 같은 대상의 현재 DB·저장소 자료, 대상이 명시된 과거 대화·첨부 순으로 사용한다.
2. 대화 제목, AI 답변, 유사 이름·이미지·파일명, 주변 정황은 단독 근거로 사용하지 않는다.
3. 원본 장비와 개조 결과 이미지, 캐릭터 초상화와 장면 이미지처럼 역할이 다른 에셋은 자동 승계하지 않는다.
4. 읽을 수 없는 첨부와 출처가 불명확한 값은 `blocked` 또는 `null`로 남긴다. 대체 이미지 생성과 수치 추정은 하지 않는다.

## 기능 결정

- 네베드 기본 개조와 깨진 음절 특수탄 제작은 별도 단계다. 깨진 음절 3개를 CENSOR-3 3발로 전환하는 제작에는 투표가 필요 없고, 실제 한 발 사용마다 Registra 과반 승인 1건을 소비한다.
- 연구소 최초 제출은 GM 전용, 추가 추출은 MAIN 캐릭터 전용이다. 결과 재료는 공용 인벤토리에 들어간다.
- ZULU-0028의 기존 Sonic Emitter 연구 설정은 유지하고 깨진 음절 탄환을 이후 일회성 후보로 구분한다.
- Nochichim은 구조화된 ID·분류·슬롯·액션을 사용하고 이름·설명에서 장비 종류를 추정하지 않는다.
- 문학과 철학이 동시에 존재하는 레코드는 별도 수치 합산 없이 `문학` 하나만 남긴다.
- CENSOR-3 투표는 Registra가 지정 채널 `1534753076399833249`에서 생성·투표·현황·과반 결론·게시 복구 원장을 관리한다. 역할과 마감은 생성 시 명시하고, `YES > 유효표/2`만 승인한다. 동률·무투표는 fail-closed로 반려한다. 승인표는 표적·세션에 묶지 않은 동질적인 한 발 사용권이며, ERP가 가장 오래된 미사용 승인부터 한 발 사용과 함께 claim하고 `voteId`·`requestRef`를 결과에 남긴다.
- 피안의 보루는 1,200 CR, 180분, TOWASKI 주담당·VERNIER 포스코어 통합 검수로 고정한다. U1은 액션 1로 거치/해제를 전환하고, 거치 중 이동 불가·맨해튼 거리의 다이아몬드 대각선 사격을 허용한다. W1은 0칸 7, 1~2칸 12, 3~4칸 12 물리와 일반 탄약 1발을 사용한다.
- 총기 피해에는 캐릭터 기본 ATK를 합산하지 않는다. 네베드의 소총 패시브 +20만 허용해 실제 표기 피해는 27/32/32가 되며, U2는 거치 중 일반 탄약 대신 CENSOR-3 실물 1발과 미사용 과반 승인 1건을 소비해 고정 30 방어 무시 심령 피해를 별도 적용한다.
- 복수 장비 액션의 충전은 액션 코드별로 분리한다. 현재 근거가 확인된 복수 충전 액션은 재장전 불가이므로, 별도 재장전 규격이 생기기 전까지 복수 액션 견적에서 재장전 가능 상태를 허용하지 않는다.
- 두 신규 카탈로그 문서는 승인 이미지를 연결한 `design-proposal`이며 master item이나 공방 blueprint 적재 입력이 아니다. `price: 0`, `isAvailable: false`, `isPublic: false`는 미확정 공임·판매·노출 정책을 대신하는 값이 아니라 오적재를 막기 위한 비공개·비판매 안전 센티널이다.

## 구현 상태

- `구현 완료`: `/erp/research` 화면과 GM 최초 제출·MAIN AGENT 추가 추출 API, 정확한 두 WebP 에셋 연결, 멱등 경제 operation과 transaction 내 재검증.
- `구현 완료`: 미스터비스트 소다 단위별 서버 판정(20% HP/SAN 1, 80% HP/SAN 10), ERP·Nochichim 소비 결과 replay, Nochichim 실제 회복의 요청별 1회 적용, commit 후 알림과 캐시 갱신.
- `구현 완료`: 신규·수정 캐릭터의 정확한 `철학` 표기를 `문학`으로 통합하고, 기존 중복값도 `문학` 하나로 정규화하는 dry-run migration과 이중 실행 가드.
- `구현 완료`: 공방 재료의 개인/공용 범위, 복수 `U` 액션, 코드별 충전, 일반 탄약·거치 프로필, 구조화된 Nochichim snapshot과 멱등 충전 소비.
- `구현 완료`: 충전형 장비 액션의 충전과 일반 탄약을 MongoDB 한 번의 조건부 갱신으로 차감하고, 멱등 replay 때 저장 당시 snapshot이 아닌 최신 장비 상태를 반환.
- `구현 완료`: Nochichim 자동 로그인 동기화에서 현재 HP/SAN은 보존하고 최대치·ATK·DEF·장비 계약만 갱신. 거치 상태는 세션 로컬이며 거치 중 플레이어 이동을 차단. 거치/회수 행동 비용, 거치 피해 보너스, 거치 중 대각선 사격 제한도 구조화 필드로만 판정.
- `구현 완료`: Nochichim 구조화 장비는 API가 전달한 명시적 `U` 액션만 노출한다. 정확한 격자 사거리가 없는 공격은 사용 불가로 닫고, `W` 공격·`R` 재장전·0~4칸 사거리·장비명 기반 분류를 새 계약에 자동 생성하지 않는다.
- `구현 완료`: Nochichim 장비 외부 차감은 요청 ID와 `PENDING → COMMITTED → LOCAL_APPLIED → APPLIED` 원장을 캐릭터 저장소에 남긴다. `LOCAL_APPLIED`에는 전장 적용 전후 snapshot과 메시지를 저장한 뒤 방·토큰·턴·대화 이력을 확정하며, 응답 유실·프로세스 재시작 뒤에는 브라우저 sessionStorage 또는 동일 fingerprint의 기존 원장 ID를 재사용한다.
- `구현 완료`: 캐릭터별 외부 장비·소모품 mutation은 처리 중 중복 실행을 차단한다. 활성 소모품 복구는 저장된 과거 인벤토리 배열을 적용하지 않고 같은 멱등 요청을 ERP에 재전송해 최신 snapshot을 받으며, 시트 조회 revision은 진행 중이거나 더 최신인 mutation 결과를 덮어쓰지 못한다.
- `구현 완료`: 구조화 `CHARGED` 액션에 기계 판정 규격이 없으면 설명을 추정해 실행하지 않고 `unsupported-effect`로 닫는다. 현재 확인된 `U3`·`U5`도 같은 fail-closed 계약으로 검증한다.
- `구현 완료`: ERP·VTT 소모품 transaction은 ACTIVE 사용자, MAIN AGENT 또는 기존 GM 소유 NPC, 소유자, 마스터 아이템 ID·slug·분류를 transaction 안에서 다시 확인한다. 응답과 알림은 사전 조회값이 아니라 commit된 소유자·코드네임·품목명을 사용한다.
- `구현 완료`: Nochichim 작전 크레딧 스킬 비용·실패 보상·undo는 요청 ID가 있는 원자적 `adjust` operation을 사용한다. 같은 요청 replay는 한 번만 반영하고, 다른 writer의 증감을 절대값 복원으로 덮어쓰지 않는다. GM의 명시적 절대값 변경만 atomic set으로 분리한다.
- `구현 완료`: 크레딧 스킬 실패 보상은 외부 보상 호출 전에 `ROLLBACK_PENDING`과 전장 snapshot을 로컬 원장에 먼저 저장한다. 저장 실패 시 보상을 호출하지 않으며, 응답 유실·프로세스 재시작 뒤 동일 보상 ID로 재개한다. 외부 응답 뒤 전장 상태를 다시 비교해 달라졌으면 과거 snapshot을 복원하지 않고 수동 정산 상태로 닫는다.
- `구현 완료`: Nochichim 캐릭터 응답에서는 장비·소모품·크레딧 스킬 내부 operation receipt를 제거한다. 완료·실패한 스킬 receipt도 전장 복구 snapshot을 폐기해 소유자·GM 응답과 archive/delta에 내부 상태가 남지 않는다.
- `구현 완료`: 공방 운영 편집기는 기존 견적의 복수 장비 액션과 전투 프로필을 편집본에 보존하며, 상태를 가진 장비 stack은 수량 1이 아니면 escrow 전에 중단한다.
- `payload 준비 완료 / 라이브 미실행`: ACCEL 시트·Argo ACTIVE 계정·세 역할별 WebP 자산과 codename resolver 연결을 확인했다. `MAIN`, `J`, 공개, `NOVUS_ORDO / MANUS / UNASSIGNED`, 잔여 포인트 0을 반영한 실행 가능 seed payload의 dry-run을 통과했다. 라이브 캐릭터 생성과 전기톱 지급은 수행하지 않았다.
- `자산·스펙 완료 / 라이브 미적재`: 사용자 확정 `피안의 보루`와 `CENSOR-3` 자산을 공방 결과·소모품 seed에 연결하고 공유 DB 완전 문서 schema 및 dry-run을 통과했다.
- `UI 뼈대 완료 / 정식 NPC 보류`: 제노의 로컬 누끼 초상, 임시 안내 카드, 상태별 무례한 대사, 이미지 fallback을 `/erp/research`에 연결했다. 영문 코드네임·신원·등급·소속은 만들지 않았고 정식 Dossier와 DB 적재는 보류했다.
- `레시피 뼈대 완료`: 등록형 ZULU 추출 레시피 계약을 만들고 현재 확정된 `ZULU-0028 격리 개체 1 → 깨진 음절 1`, 개방 후 `500 CR → 깨진 음절 1`만 등록했다. 검열된 비명 왕관을 포함한 다른 개체는 투입량·산출물·가격을 추정하지 않았다.
