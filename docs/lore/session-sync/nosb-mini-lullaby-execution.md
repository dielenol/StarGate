# 빈 창고의 자장가 1·2부 준비·검증 기록

기준일: 2026-09-10. **등록안 준비 단계다. 운영 ERP 저장·공개·배포·공적 발급은 아직 실행하지 않았다.** 부모 두 사람의 전용 초상은 사용자가 선택한 대로 자료를 받은 뒤 확정한다.

## ERP에 추가·수정한 내용:

운영 변경은 0건이다. 저장소에 보고서 2개, 같은 내용을 읽는 위키판 2개, 판테라·잔향 위키 2개, 물품 정보 2개, 부모 신원 2개와 기존 인물 5명의 보강안을 준비했다. 장면 자산 17개는 로컬 파일이며 운영 배포 전이다.

## 사용자가 확인할 내용:

- [1부 전체 검토안](nosb-mini-lullaby-part1-user-review.md), [2부 전체 검토안](nosb-mini-lullaby-part2-user-review.md): 이름 없는 화자·물품·장소를 포함한 모든 대상과 처리 이유, 부모의 필드별 등록안을 담았다.
- 시유의 어머니는 이름 미상의 연구원, 아버지는 이름 미상의 기술직이다. 둘의 나이·키·체중·정규 소속·현재 생사는 미상으로 둔다. 내부 인가 등급을 부여하지 않고 신원조회 미배정 분류를 이용한다. 생사 미확정이므로 사망 기록으로 분류하지 않는다.
- 늑구는 사용자의 최종 지시에 따라 신원 등록·연결·공적 대상에서 제외한다. 보고서 속 행동은 원문대로 보존한다. 다시 연결 대상을 묻지 않는다.
- 시유의 기존 군 경력과 인물 묘사는 보존한다. 버림받았다는 과거의 이해를 구분하고, 부모의 보호 계약과 계약 위반, 부모의 사랑을 알게 된 경위만 추가한다. 기억 속 달력으로 현재 나이나 생년월일을 바꾸지 않는다.
- 보고서는 `MINI07`과 `MINI07.5`로 준비했다. 작전지는 국가·도시 미상인 판테라 구 창고다. 임의 지리 좌표를 저장하지 않는다.
- [공적 검토안](nosb-mini-lullaby-honors-review.md): 1부는 수상 없음, 2부는 마리아의 정보·판단 공적과 아젠트의 구조·보호 공적을 각 1건 추천한다. 실제 발급은 0건이다.
- 시각 자료는 창고·연구시설·부부의 도주 등 1부 10개, 가족 사진·보호 문서·어머니와 신생아 등 2부 7개다. 보고서와 위키판에 같은 순서·설명으로 사용한다. 장면 속 인물이나 펜던트를 별도 신원 초상·물품 대표 이미지로 전용하지 않는다.

## 검토안으로만 남긴 내용 / 건드리지 않은 내용:

- 부모 두 사람은 전용 초상 미확정으로 등록 대기다. 검토용 신설 문서는 비공개 값으로 보존했다. 별도의 공개 실행 후보 파일은 앞으로 승인받을 결과를 표현하며 이미 공개했다는 뜻이 아니다.
- 기존 인물 5명은 마리아, 발레리아 아젠트, 키아나 오 캘러핸(네베드), 이동식, 시유다. 기존 권한·소속·직업·초상·성격 본문을 바꾸지 않고 등장·관계·성격 관찰을 추가한다. 시유의 배경 수정만 기존 원문을 비교하는 조건을 둔다.
- 익명 의무담당·연구시설 팀장·두 판테라 병사·추적자와 기억 속 적대 개체는 독립 신원으로 만들지 않는다. 잔향은 어머니 본인이나 영혼과 구분해 위키에 기록한다.
- 자장가 레코드와 가족 사진 펜던트는 판매 불가 물품 정보로 준비했다. 펜던트 1개를 시유에게 지급하는 것은 별도 실행 후보다. 시유의 현재 인벤토리 7행과 연결 품목 7건에 해당 물품 중복은 없었지만, 지급 승인과 실행 직전 재확인이 필요하다.
- 건빵·육포의 최종 보관, 소다 사용 수량, 기억 속 장비 파손은 불명확하여 재고·크레딧·장비 상태를 변경하지 않는다. 알림도 보내지 않았다.

## 이번 작업에서 끝낸 내용:

- 원본 82쪽 전체를 읽고 화자·행동·날짜·장면을 독립 대조했다. 1부 29대상, 2부 33대상의 처리안을 기록했다.
- 부모 관계와 성격 관찰에서 1부 사실이 2부 출처로 붙은 부분을 수정했다. 시유의 기존 인물 묘사를 보존했고, 위키의 노부스·아버지 연결을 보강했다. 원문 재검토에서 추가 수정 사항은 없었다.
- 부모 규격 2개와 물품 규격 2개, 등장 14건·관계 12건·성격 관찰 9건의 구조와 본문 일치를 확인했다. 부모의 관찰 4건은 초상 확정 전 적용 대기다.
- PDF의 고유 이미지 182개를 검토하고 회차별 시각 원장 126행·128행을 남겼다. 장면 17개를 원본 구도 그대로 1400×680 WebP로 준비하고 최종 파일을 눈으로 확인했다.
- 기존 MINI06 보고서와 위키판의 실제 표시를 읽기 확인했다. 새 보고서 번호·분류와 별도 목록 항목, 이미지 경로·순서·대체 설명·캡션 일치 검사를 통과했다.
- 운영 등록 파일의 동일 이름 충돌 위험과 V 보고서의 비공개 신원 참조 문제를 고쳤다. 신규 내용 전체와 생성일이 일치할 때만 같은 기록을 재사용하며, 충돌하면 덮어쓰지 않고 중단한다.

## 아직 끝나지 않은 일:

부모 초상 2개 확정, 최종 공개·운영 저장·배포·공적 발급 범위 승인, 승인 범위 실행과 저장 후 화면 검증이 남았다. 이를 완료한 동기화로 표현하지 않는다.

운영 DB를 읽는 최종 실행 예행 검사는 인덱스 문제 0건이며, 아직 존재하지 않는 부모 두 명을 가리키는 보고서 2건에서 참조 차단이 남았다. 부모 저장 후 다시 검사해야 한다. 새 기록의 운영 지도 카드 겹침, 보고서·위키·신원조회·물품·갤러리·검색·명예의전당 표시 및 공개 등급별 접근은 아직 확인하지 않았다.

## 진행에 필요한 확인·자료:

사용자가 **“전용 초상을 정한 뒤 등록안 마무리”**를 선택했으므로 시유의 어머니와 아버지의 신원조회용 초상이 필요하다. 사용자가 두 장을 제공하거나 별도로 생성을 요청하면 해당 방식으로 준비한다. 부부 사진 장면은 이미 보고서 자료로 채택했지만 전용 초상으로 승인받은 자료는 아니다.

초상까지 확정하면 보고서 2개·위키 4개·신원 2개·기존 인물 5명 보강·판매 불가 물품 정보 2개·장면과 초상 배포·공적 2건 발급 및 1부 무수상 처리에 대한 통합 실행안을 제시한다. 펜던트의 실제 인벤토리 지급은 카탈로그 등록과 구별해 제시한다. 이전 7화 2부의 공개·발급 승인은 이번 미니세션에 재사용하지 않는다.

## 다음에 할 일:

1. 초상 자료를 받으면 원본을 보존하고 신원조회 자산으로 준비한다. 배경이 있으면 `local-cutout` 절차와 실제 투명 픽셀·여러 배경에서의 검사를 거친다. 부모 원장·규격·공개 실행 후보의 초상과 공개값을 일치시킨다.
2. [비공개 검토 데이터](nosb-mini-lullaby-review-payload.json)는 검토 입력이다. 운영 실행에는 사용하지 않는다. 완성된 실행 후보는 [부모 등록](../../../StarGateV2/scripts/seed-payloads/nosb-mini-lullaby-parents-create.json) 6개 연산과 [공개 반영](../../../StarGateV2/scripts/seed-payloads/nosb-mini-lullaby-publication.json) 32개 연산으로 나눴다. 부모 파일은 신원 2개와 성격 관찰 4개, 공개 반영 파일은 나머지 문서와 기존 인물 보강이다.
3. 유효한 전체 승인 후 자산 배포·확인을 진행하고, 부모 공개 신원을 먼저 저장·재조회한다. 이어 공개 반영 파일의 예행 검사와 원장 준비 상태를 다시 통과시킨 뒤 실행한다. 두 실행 파일은 각각 한 트랜잭션이며 한 명령으로 함께 저장하지 않는다. 부모 저장 후 두 번째 단계가 실패하면 부모만 공개된 부분 상태가 남는다. 자동 원복하지 않고 중단·재검증 후 두 번째 파일을 재실행한다.
4. 초기 생성 파일의 필터는 생성일과 원하는 지속 내용 전체를 비교한다. 수정 시각과 도구가 관리하는 보고서 출처, 부모 관찰 배열은 비교에서 제외한다. 동일본 재실행은 가능하지만 후속 세션이 배경·관계 배열을 확장한 뒤에는 이 생성 파일을 재사용하지 않고 새 변경 전후 비교 파일을 준비한다.
5. 물품 파일은 판매 불가·가격 0인 존재 기록을 생성하므로 runner의 경제 필드 확인 옵션도 필요하다. 이 옵션을 이유로 인벤토리 지급이나 가격·재고 변경까지 실행 범위를 넓히지 않는다.
6. 공개 보고서의 최종 내용과 실제 대상 인물을 다시 읽고, [공적 계획](nosb-mini-lullaby-honors-review.json)을 공식 전체 계획에 합친다. 두 보고서만 대상으로 발급·무수상 처리를 실행하고 해당 기록이 `CURRENT`인지 원장·보고서·신원조회·명예의전당에서 확인한다. 알림은 별도 승인 없이는 보내지 않는다.
7. 각 소비 화면의 링크·이미지·공개 접근과 지도 카드 표시를 직접 확인한 뒤 이 기록을 실제 결과로 갱신한다.

## 실제로 확인한 내용:

- `pnpm typecheck`, `pnpm lint`, `git diff --check`: 통과.
- 번호 15건, 목록 3건, 이미지 마크다운 3건, 자산 18건: 총 39건 통과. 신규 테스트의 잘못된 `main` 기대값은 실제 enum인 `regular`로 수정 후 해당 15건을 재검증했다.
